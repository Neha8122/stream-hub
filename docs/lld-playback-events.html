Playback Events LLD

Pressing play and watching produces a stream of events. They go through Kafka to a consumer that keeps "continue watching" and total watch time up to date. Kafka delivers every message at least once, so the consumer has to make a second delivery harmless.

KeyuserIdone user's events land on one partition, in order; users spread across partitions
Produceracks=all, idempotent produceran event isn't lost if a broker dies, and a producer retry doesn't write it twice
Watched secondscomputed by playback from the session, clamped to 0..60a player that retries a heartbeat sends the same position again, which adds 0; a bogus position can't add hours
Progresskept only if the event is neweridempotent and safe when events arrive late or twice
Watch timeincrement, guarded by processed_events in the same transactionincrements are the non-idempotent part; the guard makes them happen once
Offsetscommitted after the transactionat-least-once: nothing lost, duplicates handled above
Bad messages3 retries, then the dead-letter topicone poison message must not block every user on that partition
