Resilience LLD

The home page is built from several services at once. Any of them can be slow or down at any moment. The rule: the page always loads, fast, with whatever is healthy, and a failing dependency is left alone to recover instead of being hammered.

2 · The circuit breaker: stop calling what's broken

3 · The other three tools

ToolWhat it preventsSetting here
Timeouta slow dependency holding a request open foreverhistory 150 ms, catalog 200 ms, capped by the page deadline
Bulkheadone slow dependency using up every thread, so even healthy rows can't be served. Named after the walls that stop one flooded compartment sinking a shipat most 20 calls in flight to history, 30 to catalog; the rest get their fallback at once
Retrya single dropped connection or brief blip failing the row1 retry after 30–60 ms (with jitter), only for reads, never when the breaker is open, never past the deadline
Fallbackan error pagecatalog rows: last good copy; continue watching: empty. The response says what was degraded

Order around each call: bulkhead → circuit breaker → retry → HTTP call with timeout. Retries happen inside the breaker, so a retry storm is counted as failures and opens it.
